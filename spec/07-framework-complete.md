# The Framework Complete

Parts I, II, III and IV together define a complete FieldWorks deployment. A conformant protocol adapter for every data source. A topology.yaml that describes the facility honestly, including its imperfections. An aggregator.json that scopes the protocol surface to the agent layer. Five agents that observe, reason, validate, and act within defined limits. A five-store memory layer that accumulates plant knowledge across sessions. An audit trail that records everything. A trust mode that the facility controls.

Part V puts many such deployments under one enterprise, without merging them. Each plant keeps its own stack, its own operators and its own controls. The enterprise layer asks plants questions, never gives them orders.

The waterworks-ai reference implementation demonstrates all of it running. It is the spec made real. When the spec is ambiguous, the reference implementation is authoritative.

What FieldWorks does not do is as important as what it does. It does not replace the control system. It does not assume the plant is clean. It does not act without a record. It does not grant autonomy by default. It does not know more than the topology tells it.

What it does is give every facility, regardless of the age of its infrastructure or the protocols it runs, the same thing. A natural language interface backed by agents that know the plant, respect its limits and earn the trust they are given.
